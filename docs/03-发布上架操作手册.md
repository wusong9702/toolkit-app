# 发布上架操作手册

> 前置：代码已推到 GitHub，网页版已能正常访问
> 目标：打出 iOS / Android 安装包并上架到两大应用商店

---

## 零、先看全局

| | Android | iOS |
|---|---|---|
| 开发者账号 | 25 美元一次性 | 99 美元/年 |
| 构建环境 | 你的 Windows 电脑 | 云 Mac（GitHub Actions） |
| 证书创建 | 本地生成 keystore | 网站申请，不需要 Mac |
| 上架文件格式 | AAB | IPA |
| 审核时长 | 几小时 ~ 2 天 | 1 ~ 7 天 |
| 拒审风险 | 低 | 中高 |

**建议顺序：先上 Android。** Google Play 审核宽松、速度快，你能快速走完一遍完整流程、把坑踩完，再去啃 iOS 会顺利得多。

## 一、上架前必做的准备

### 1. 改掉默认包名（现在就改，否则后患无穷）

打开 `app/capacitor.config.ts`：

```ts
appId: 'com.example.toolkit',   // ← 改成你自己的，例如 com.wusong.toolkit
appName: '工具箱',               // ← 改成你的应用名
```

**包名规则：** 通常是域名的倒写 + 应用名。没有域名就用 `com.你的名字.应用名`。

**警告：** 应用上架后包名无法修改。改包名等于换一个新应用，老用户收不到更新。

### 2. 准备应用图标和启动图

最简单的方法——用现成工具一次性生成所有尺寸：

- 在线工具：**App Icon Generator**（搜这个名字有一堆）
- 或者本地：装 `npx @capacitor/assets` 自动生成（需要准备一张 1024×1024 的源图）

```bash
cd app
npx @capacitor/assets generate --iconBackgroundColor '#1989fa'
```

### 3. 准备隐私政策网址

**两个商店都强制要求提供隐私政策链接**，没有的话审核直接拒。

你的应用数据只存在本地、不收集用户信息，写一个简单声明即可。可以直接放在 GitHub Pages 上：

新建 `app/public/privacy.html`，写清楚"本应用不收集任何个人信息，所有数据仅存储在用户设备本地"。

### 4. 准备商店素材

| 素材 | Android | iOS |
|---|---|---|
| 应用图标 | 512×512 PNG | 1024×1024 PNG（无透明、无圆角） |
| 手机截图 | 至少 2 张，建议 4-6 张 | 6.9 英寸必备，建议多尺寸 |
| 简短描述 | 80 字符内 | — |
| 完整描述 | 4000 字符内 | 4000 字符内 |
| 关键词 | — | 100 字符内，逗号分隔 |

## 二、Android 上架完整流程

### 步骤 1：安装 Android Studio

1. 下载：https://developer.android.com/studio
2. 安装时勾选 **Android SDK**、**Android SDK Platform**、**Android Virtual Device**
3. 安装完成后打开，首次启动会下载 SDK，等它跑完
4. 进入 **More Actions → SDK Manager**，确认装了 **Android SDK Build-Tools** 和 **Android SDK Platform 34+**

配置环境变量（让命令行能找到 Android）：

```bash
# 加到 ~/.bashrc 或系统环境变量
export ANDROID_HOME=$HOME/AppData/Local/Android/Sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools
```

验证：重开终端，输入 `adb version` 能看到版本号。

### 步骤 2：生成 Android 原生工程

```bash
cd app
npx cap add android
npx cap sync android
```

这一步会在 `app/` 下生成 `android/` 目录，那就是一个标准的 Android 原生工程。

### 步骤 3：本地调试

想直接把应用装到手机上调试：

1. 手机开启 **开发者选项**（设置 → 关于手机 → 连点"版本号"7 次）
2. 开启 **USB 调试**
3. 数据线连电脑，手机上点"允许调试"
4. 执行：

```bash
npx cap run android
```

应用会自动装到手机上并打开。

> 也可以在 Android Studio 里点绿色三角运行，报错信息更直观。用 `npx cap open android` 打开工程。

### 步骤 4：生成签名密钥（只做一次，然后好好备份）

```bash
keytool -genkey -v -keystore my-release-key.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias my-key-alias
```

会问你一系列问题，如实填即可。最后设两个密码（密钥库密码和密钥密码，可以设成一样的）。

⚠️ **这个 `.jks` 文件丢了，你就永远无法再更新这个应用了。** 立刻备份到网盘 + U 盘。同时把密码记在密码管理器里。

### 步骤 5：配置签名

编辑 `app/android/app/build.gradle`，在 `android { }` 块里加：

```gradle
signingConfigs {
    release {
        storeFile file("../../my-release-key.jks")
        storePassword "你的密钥库密码"
        keyAlias "my-key-alias"
        keyPassword "你的密钥密码"
    }
}
buildTypes {
    release {
        signingConfig signingConfigs.release
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
    }
}
```

> 密码写在文件里会被提交到 Git。正式项目建议用 `keystore.properties` 方式，配合 `.gitignore` 排除。仓库里的工作流已经用了 properties 方案。

### 步骤 6：构建上架用的 AAB

```bash
cd android
./gradlew bundleRelease
```

产物在 `app/android/app/build/outputs/bundle/release/app-release.aab`

想要能直接安装的 APK（发给别人测试用）：

```bash
./gradlew assembleRelease
```

产物：`app/android/app/build/outputs/apk/release/app-release.apk`

### 步骤 7：注册 Google Play 开发者

1. 打开 https://play.google.com/console
2. 支付 25 美元注册费（一次性，终身有效）
3. 账号审核约 1-2 天

### 步骤 8：创建应用并上架

1. 控制台 → **创建应用** → 填名称、语言、应用类型、免费/付费
2. 按左侧清单逐项完成：
   - **应用内容**：隐私政策、广告声明、内容分级问卷、目标受众
   - **商店信息**：描述、截图、图标、分类、联系方式
   - **正式版**：上传 AAB
3. 全部完成后点 **发布**

**首次上架需要走"内容分级"和"数据安全"问卷**，如实填写即可。你的应用不联网收集数据，大部分选"否"就行。

审核通常几小时到两天。第一次上架可能慢一些。

## 三、iOS 上架完整流程

### 关键认知：只有"编译打包"需要 Mac

| 环节 | 需要 Mac？ |
|---|---|
| 注册开发者账号 | ❌ |
| 创建证书和描述文件 | ❌ 网站操作即可 |
| 填写 App Store Connect 信息 | ❌ 网页操作 |
| **编译打包出 IPA** | ✅ **这一步用云 Mac** |
| 上传 IPA | ❌ 可用 Windows 工具 |

所以你要做的，就是把证书准备好，让 GitHub 的云 Mac 替你编译。

### 步骤 1：注册 Apple 开发者账号

1. 打开 https://developer.apple.com/programs/
2. 用 Apple ID 登录，支付 99 美元/年
3. 个人信息填真实信息，**公司/个人选择要慎重**：
   - 个人账号：开发者名称显示你的真名
   - 公司账号：需要邓白氏编码（D-U-N-S），申请要几天
4. 审核约 1-2 天

### 步骤 2：在 Windows 上创建证书（不需要 Mac）

**2.1 生成证书请求文件（CSR）**

用 OpenSSL（Git Bash 自带）：

```bash
openssl req -new -newkey rsa:2048 -nodes \
  -keyout ios_distribution.key \
  -out ios_distribution.csr \
  -subj "/emailAddress=你的邮箱/CN=你的名字/C=CN"
```

**2.2 上传 CSR，下载证书**

1. 登录 https://developer.apple.com/account
2. **Certificates** → `+` → 选 **Apple Distribution** → 上传 `ios_distribution.csr`
3. 下载生成的 `distribution.cer`

**2.3 转成 p12 格式**

```bash
# cer 转 pem
openssl x509 -inform DER -in distribution.cer -out distribution.pem

# 合成 p12（会要求设一个导出密码，记住它，后面填到 Secrets）
openssl pkcs12 -export \
  -inkey ios_distribution.key \
  -in distribution.pem \
  -out ios_distribution.p12
```

**2.4 创建 App ID**

1. **Identifiers** → `+` → **App IDs** → **App**
2. Bundle ID 选 **Explicit**，填你在 capacitor.config.ts 里设的 appId（如 `com.wusong.toolkit`）
3. 勾选需要的服务（默认即可）

**2.5 创建描述文件（Provisioning Profile）**

1. **Profiles** → `+` → **App Store**（上架）或 **Ad Hoc**（测试）
2. 选刚才的 App ID → 选刚才的证书 → 命名 → 下载 `.mobileprovision` 文件

### 步骤 3：把证书填进 GitHub Secrets

在仓库页面 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| Secret 名称 | 值从哪来 |
|---|---|
| `IOS_CERTIFICATE_BASE64` | p12 文件转 base64：`base64 -w 0 ios_distribution.p12` |
| `IOS_CERTIFICATE_PASSWORD` | 步骤 2.3 里你设的导出密码 |
| `IOS_PROVISIONING_PROFILE_BASE64` | mobileprovision 转 base64：`base64 -w 0 文件名.mobileprovision` |
| `IOS_TEAM_ID` | 开发者账号页面右上角，或者 membership 页面里的 Team ID |
| `KEYCHAIN_PASSWORD` | 随便设一个字符串，比如 `temp-keychain-pwd-2026` |

Windows 上转 base64（Git Bash 里执行）：

```bash
base64 -w 0 ios_distribution.p12 > p12.txt
base64 -w 0 你的应用名.mobileprovision > profile.txt
```

然后把文件内容整段复制粘贴。

### 步骤 4：生成 iOS 工程并推送

```bash
cd app
npx cap add ios
npx cap sync ios
git add .
git commit -m "chore: 添加 iOS 原生工程"
git push
```

> `ios/` 目录需要提交到仓库，云 Mac 才有的构建。注意 `.gitignore` 里确保没把它排除掉。

### 步骤 5：云端构建

```bash
git tag v1.0.0
git push origin v1.0.0
```

或者手动触发：仓库 → **Actions** → "构建 iOS 安装包" → **Run workflow** → export_method 选 `app-store`。

等 10-15 分钟，在 Artifacts 里下载 `.ipa` 文件。

**免费额度说明：** 公开仓库免费无限使用；私有仓库每月 2000 分钟额度，macOS 按 10 倍计费（相当于约 200 分钟），够打十几个包。

### 步骤 6：上传到 App Store

**方法 A：用 Transporter（Windows 官方工具，推荐）**

1. Microsoft Store 搜索安装 **Transporter**
2. 用 Apple ID 登录
3. 把 `.ipa` 拖进去 → **交付**

**方法 B：让 GitHub Actions 自动上传**

在工作流末尾加一步（需要 App Store Connect API 密钥）：

```yaml
- name: 上传到 App Store Connect
  run: xcrun altool --upload-app \
    -f $RUNNER_TEMP/export/*.ipa \
    -t ios --apiKey ${{ secrets.ASC_API_KEY_ID }} \
    --apiIssuer ${{ secrets.ASC_API_ISSUER }}
```

### 步骤 7：App Store Connect 配置

1. 登录 https://appstoreconnect.apple.com
2. **我的 App** → `+` → 新建 App，选刚才的 Bundle ID
3. 填写：
   - **App 信息**：名称、副标题、分类、隐私政策网址
   - **价格与销售范围**：选免费或定价
   - **准备提交**：上传截图（6.9 英寸 iPhone 必须有）、填描述、关键词、技术支持网址
   - **构建版本**：选刚才上传的构建
4. 点 **提交以供审核**

## 四、常见拒审原因（Apple 尤其严格）

| 拒审理由 | 怎么避免 |
|---|---|
| 4.2 最低限度功能 | 应用太简单会被判"就是个网页"。功能要做扎实，有实际使用价值 |
| 5.1.1 数据收集 | 用到相机/位置等权限，必须在描述里写清楚用途 |
| 2.1 信息不完整 | 截图、描述、隐私政策、演示账号都要齐全 |
| 3.1.1 应用内购买 | 应用内不能引导用户去外部支付 |
| 4.3 重复应用 | 别一次上架多个功能雷同的应用 |

**被拒了不要慌**，审核员会写明原因，按要求改完重新提交即可。沟通态度诚恳一点，通过率会高。

## 五、上架后的日常

- **版本更新**：改代码 → 改 `package.json` 里的 version → 打新标签 → 自动构建 → 上传 → 提交审核
- **紧急修复**：Google Play 支持分阶段发布，先放 10% 用户试水
- **崩溃监控**：接入 Firebase Crashlytics（免费），能第一时间知道线上问题
