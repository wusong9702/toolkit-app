# 跨平台应用技术方案

> 目标：支持 iOS + Android 的工具类应用
> 定位：新手可操作，分阶段交付，每阶段都有可见成果
> 日期：2026-09-01

---

## 一、先说结论

**用一套网页代码（Vue 3），通过 Capacitor 打包成 iOS 和 Android 原生应用。**

这条路的好处对新手来说是压倒性的：

| | 网页套壳方案（推荐） | 原生开发 | Flutter |
|---|---|---|---|
| 学一门技术覆盖两端 | ✅ | ❌ 要学 Swift + Kotlin 两套 | ✅ |
| 你能立刻上手 | ✅ 会点 HTML 就能改 | ❌ 门槛很高 | ⚠️ 要学 Dart |
| 改完立刻看到效果 | ✅ 浏览器刷新 | ❌ 每次编译几分钟 | ⚠️ 热重载尚可 |
| 中文资料丰富度 | ✅ 极丰富 | 中等 | 中等 |
| 性能上限 | 够用（工具类绰绰有余） | 最高 | 高 |
| 能不能上架 | ✅ | ✅ | ✅ |

**关键判断：你是做工具类应用，不是做游戏或重度动画应用。** 工具类应用 95% 的界面是列表、表单、按钮——这些用网页技术做和原生做，用户根本分辨不出来。为了那 5% 的理论性能差距去学两套原生技术栈，不划算。

## 二、技术选型

| 层 | 选择 | 为什么选它 |
|---|---|---|
| 框架 | Vue 3 | 中文文档和社区最厚，遇到问题搜一下就有答案。单文件组件 `.vue` 结构直观，新手友好 |
| 构建 | Vite 6 | 启动快到几乎无感，改代码保存后浏览器立刻更新 |
| UI 库 | Vant 4 | 国内移动端组件库的事实标准，有赞维护，组件齐全，中文文档 |
| 状态 | Pinia | Vue 官方推荐，比老版 Vuex 简单很多 |
| 离线 | vite-plugin-pwa | 让网页能"安装到桌面"，断网也能打开 |
| 打包 | Capacitor 7 | 把网页包成原生 App。Ionic 出品，比 Cordova 现代，插件生态够用 |
| 语言 | TypeScript | 有类型提示，改代码时编辑器会主动告诉你哪里错了 |

## 三、为什么先做网页版（这是关键决策）

你选了"先做网页版"，这个选择很对。原因有三：

1. **反馈最快。** 改一行代码，浏览器刷新就能看。不用等编译、不用连手机、不用装模拟器。
2. **排错最容易。** 网页有 Chrome 开发者工具，报错直接显示在控制台。原生 App 出问题，光是拿到日志就要折腾半天。
3. **风险最低。** 万一做到一半发现方向不对，网页版的沉没成本最小。

**但要注意：网页版不是终点，是起点。** 同一套代码后面会原封不动地变成 App，所以从第一行代码开始就要遵守几个约定：

- 路由必须用 **hash 模式**（地址带 `#`）——App 内是本地文件加载，普通路径会找不到资源导致白屏。脚手架里已经配好了。
- 所有网络请求要考虑**断网兜底**——手机网络不稳定是常态。
- 数据要能**本地持久化**——工具类应用断网也该能用。

这几条我已经在脚手架里处理好了，你照着现有模块扩展就行。

## 七、必须提前知道的坑

### 1. iOS 必须有 Mac —— 但有绕开办法

Apple 强制要求 iOS 应用必须在 macOS 上构建。你没有 Mac，解决方案有两个：

- **GitHub Actions macOS 虚拟机**（已配好，推荐）：免费额度够用，工作流文件已经写好了。
- 租用云 Mac（如 MacinCloud）：约 100-200 元/月，需要长时间调试时才划算。

### 2. 应用包名一旦定下几乎改不了

`com.example.toolkit` 这个包名是应用的身份证，上架后无法修改。**现在就改成你自己的**，比如 `com.你的域名.应用名`。改在 `app/capacitor.config.ts` 里。

### 3. 签名文件丢了就完蛋

Android 的 keystore 文件一旦丢失，**你再也无法为这个应用发布更新**，只能换个包名重新上架，老用户无法升级。这个文件要备份到网盘 + U 盘两个地方。

### 4. Apple 审核比 Google 严得多

- Google Play：通常几小时到两天过审
- App Store：1-7 天，且**拒审率不低**

常见拒审原因：功能太简单（"就是个网页"）、没有隐私政策、截图和实际不符、免费应用里有付费引导。工具类应用尤其容易被以"内容过于简单"为由拒绝——所以功能要做扎实，别只放一个空壳。

### 5. 网页套壳不是免死金牌

如果应用明显就是个网站（比如满屏外链、没有原生交互、断网一片空白），Apple 会拒。**必须有实质性的原生体验和离线可用性**——这也是为什么脚手架里 PWA 和本地存储一开始就要做好。

## 八、现在你该做什么

1. 打开 `app/src/views/LedgerView.vue`，看看一个完整功能模块长什么样
2. 照着它的结构，把你自己的功能加进去
3. 改 `app/capacitor.config.ts` 里的 appId 和 appName
4. 改 `app/public/content/categories.json`，换成你自己的内容
5. 跑 `npm run dev` 看效果，改到满意为止
6. 然后进入阶段二，按 `docs/02-GitHub与自动构建.md` 连 GitHub

## 九、什么时候该重新考虑技术选型

以下情况出现时，网页套壳方案可能不再合适，需要换成 Flutter 或原生：

- 应用核心是相机/图像处理、AR、实时音视频
- 需要复杂手势和 60fps 动画（如绘图、游戏）
- 需要深度系统集成（后台定位、蓝牙硬件、桌面小组件）
- 用户量上来后性能瓶颈明显

**对你现在的工具类应用来说，这些都不成立。** 放心用。
